# Лабораторная 4 — задачи Тёмыча: desktop HL7-импортёр, v1

Дата: 13.11.2026. Исполнитель: **Тёмыч**. Парная карточка: [задачи Льва](lab4-lev-tasks-v1.md).

Это план новой реализации по «Лабораторной 4». Твоя часть — **отдельное десктопное приложение**, которое читает XML преподавателя, получает сервисные токены по HTTPS и отправляет пациентов в HIS по HL7 v2.8 / MLLP / mTLS. Работать предстоит не в текущей веб-LIS. Лев реализует сторону HIS.

Сложность поделена поровну: **40 SP тебе и 40 SP Льву**. SP обозначают относительную сложность с тестами, не часы. Ты получаешь полноценные задачи по безопасному хранению, протоколам и desktop, а не только UI. При этом код двух приложений можно писать параллельно. После изучения XML при существенном расширении объёма обе оценки пересматриваются вместе.

## 1. Что делать и где проходит граница

- Новый Go-модуль/репозиторий, предлагаемое название `hl7-import-client`. Не добавлять приложение внутрь серверного Go-процесса LIS и не подменять desktop браузерной страницей.
- Предлагаемый GUI — **Fyne**, пригодный для нативного приложения на macOS. Это проектный выбор, не требование задания. Зафиксировать Go/Fyne/dependency versions в первом PR и проверить системные зависимости сборки на своей машине.
- Слои: desktop UI → application use cases → XML/HL7/auth/MLLP/storage adapters. UI не занимается socket I/O и XML parsing напрямую.
- Самостоятельная PostgreSQL/SQLite не обязательна: в лабораторной 4 нет требования постоянной локальной медицинской истории. Для первой версии хватит защищённых настроек и результатов текущего запуска в памяти. Сохранение отчёта можно сделать явной пользовательской операцией.
- Не менять HIS, его БД/миграции/FHIR и существующую LIS. Медицинские данные передаются в HIS только по MLLP; HTTPS нужен для токенов и теста подключения.
- Каждая задача T1–T8 — отдельная ветка и PR в репозитории desktop; независимые PR в `main`, зависимые со своей явной базой. Самостоятельно не вливать чужие PR.

**Единый источник wire-формата:** [C4-v1 в карточке Льва](lab4-lev-tasks-v1.md#3-общий-технический-контракт-c4-v1). В новом репозитории сослаться на файл/зафиксированный коммит HIS и скопировать fixtures с указанием хешей. Не вести вторую несогласованную версию полей и ACK.

## 2. Коротко о протоколе

1. Пользователь создаёт в HIS сервисный аккаунт `HL7 Import`, копирует однократно показанный API key.
2. В desktop задаёт **раздельно** HTTPS base URL и MLLP host/port, CA для проверки сервера, client certificate/private key для MLLP.
3. Через обычный HTTPS клиент предъявляет API key, получает access/refresh, вызывает `/api/testConnection`. Клиентский сертификат для HTTPS не требуется.
4. Отдельно проверяет mTLS/MLLP стандартным тестовым обменом C4. Один TLS handshake без сообщения — недостаточная проверка.
5. Выбирает XML и видит распознанных пациентов до отправки.
6. На каждого пациента строится ADT A28 с PID/DG1 и **access JWT в UAC**. Для каждого — один MLLP кадр и отдельный ACK.
7. При `AA` из MSA-3 берётся UUID пациента HIS, при `AE/AR` — безопасная ошибка. Ответ привязывается к исходному MSH-10 через MSA-2.
8. На timeout после отправки показывается «Исход неизвестен» без автоматического повторения пациента. Повторная отправка по инициативе пользователя может вернуть duplicate.

**Не путать:** mTLS подтверждает доверенный сертификат соединения, JWT даёт право импорта. Subject CN клиента нужен для справки, не заменяет аккаунт/роль. Название аккаунта и имя файла не являются ID пациента.

## 3. Что пока неизвестно

**XML преподавателя не приложен к постановке задач.** Пока нельзя достоверно указать имена тегов, namespace, вложенность диагнозов, формат пола и дополнительных полей. В T3 нужно получить реальный образец и сделать mapping. Остальные части разрабатываются на нормализованных синтетических пациентах и согласованных HL7 fixtures.

UAC ED-компоненты и тестовый NMD/N02 → ACK envelope предложены в C4; они подтверждаются byte-fixtures в L1/T1. Не нужно ждать готового HIS, но нельзя начинать кодировать спорные поля двумя разными способами. Решения из C4 и его fixtures имеют приоритет над разрозненными примерами из интернета.

## 4. Карточки задач Тёмыча

### T1. Desktop-каркас, контракты и fake HIS — 5 SP

**Что реализовать**

- Создать Go-модуль, нативное окно Fyne с разделами **«Импорт»**, **«Настройки»**, **«Диагностика»**. После сборки приложение запускается как desktop, без предварительного браузера.
- Предлагаемая структура:

```text
cmd/import-client/
internal/domain/          # нормализованные Patient/Diagnosis и результат строки
internal/application/     # Connect, Probe, LoadFile, ImportBatch
internal/ports/           # интерфейсы, не зависят от Fyne/net.Conn
internal/adapters/xml/    # XML → нормализованные пациенты
internal/adapters/hl7/    # ADT/UAC, ACK, test query
internal/adapters/hisauth/
internal/adapters/mllp/
internal/adapters/settings/
internal/ui/              # Fyne views/presenters
internal/testsupport/     # fake auth, mTLS MLLP server
tests/fixtures/lab4/
```

- Интерфейсы примерного уровня: `PatientSource.Read(ctx, reader)`, `Hl7Codec.EncodePatient/DecodeAck`, `AuthClient.Token/Refresh/TestConnection`, `MllpClient.Exchange`, `SettingsStore`, `BatchImporter`. Имена свободны; транспорт и GUI должны заменяться fake-реализациями.
- С Левом проверить C4: UTF-8/framing/escape, UAC credential type и ED, MSH-10/MSA-2, MSA-3, probe и лимиты. Скопировать byte-fixtures с версией источника. Образцы с настоящими токенами запрещены.
- Собрать fake HTTPS/mTLS HIS для независимых тестов: token/refresh/probe, ADT → AA/AE/AR, timeout, неверная correlation. Runtime-код не должен уметь молча переключаться на fake.

**Зависимости:** UI/ports можно начать сразу; fixtures согласуются с L1, живой HIS не нужен.

**Готово, когда:** окно запускается на macOS, архитектурные тесты/codec fixtures доступны, mock-передача проходит без HIS; указано, что именно ещё не реализовано.

### T2. Настройки, HTTPS auth и безопасное хранение — 5 SP

**Что реализовать**

- Поля: название профиля, HTTPS URL, MLLP hostname/port, server CA file, client certificate PEM и matching private key PEM, API key. Если HTTPS и MLLP используют разные trust roots — отдельные настройки, а не отключение проверки.
- Validate пути/формат файлов, пару cert/key, срок клиента, URL scheme и порт. Client certificate не использовать автоматически в HTTPS auth: mTLS относится только к MLLP.
- API key сохранять через системный keychain/credential store. В настройках можно хранить путь к private key с ограниченными правами, не его содержимое; ошибку доступа объяснять пользователю. Не складывать API key/refresh в plaintext JSON или Fyne preferences.
- Для первой версии токены можно держать только в памяти процесса. При перезапуске новая сессия получается сохранённым API key. Если токены сохраняются — только secure store, не собственное слабое шифрование и не ключ рядом с ciphertext.
- Реализовать текущие HTTPS endpoints HIS без изменения их JSON. Перед отправкой пациента обновлять почти истёкший access по refresh; rotation сохраняет новую пару атомарно. При отказе refresh — явное переподключение, без бесконечного fallback на API key.
- **«Проверить HTTPS»** показывает результаты TLS verification, Subject/Issuer, validity, SAN и SHA-256 fingerprint реального server certificate, затем итог `/api/testConnection`. Это certificate HTTPS-соединения; не выдавать его за проверку MLLP endpoint.
- При смене URL/профиля/ключа очищать старые tokens и connection status; никогда не отправлять токен одного профиля другому адресу. TLS/CA errors показывать отдельно от 401/403/timeout.

**Зависимости:** fake HTTPS из T1; L2 потребуется только для живой проверки.

**Готово, когда:** положительные и отрицательные HTTP/TLS tests проходят; секреты отсутствуют в обычных settings/logs; после перезапуска profile восстанавливается, права подтверждаются реальным ответом сервера.

### T3. XML преподавателя → нормализованные пациенты — 8 SP

**Что реализовать**

- Получить образец XML. Сделать таблицу **XML path/namespace → Go field → HL7 field → HIS destination**, включая все поля файла. Согласовать новые поля с Левом, если текущего C4 недостаточно.
- Парсер потоковый на `encoding/xml` либо эквиваленте с лимитами. Запретить DTD/custom entities, внешние ресурсы и неконтролируемое расширение; отсутствие XXE проверить тестом. Ограничить размер файла, число пациентов, длины значений и количество диагнозов; значения лимитов записать в документации.
- Поддержать фактическую кодировку файла. Если стандартный Go decoder не умеет заявленную кодировку, явно подключить ограниченный charset decoder или показать понятную ошибку; не декодировать произвольные байты как UTF-8.
- Проверять внешний ID, имена, даты, пол, диагнозы. Сохранять ведущие нули ID, не выводить пол из имени и не преобразовывать неизвестную дату в zero-value. Возраст не заменяет дату рождения.
- Повтор внешнего ID в выбранном файле выявлять до отправки. Не объединять людей по ФИО. Повтор кода диагноза у пациента обрабатывать по C4; разные имена одного нового кода не замалчивать.
- Синтаксически сломанный XML прекращает разбор с позицией. При корректном XML с недопустимой одной записью UI может пометить эту запись и дать импортировать остальные; никакие строки не отправляются молча до явного запуска пользователем.
- Парсер не создаёт HL7 и не пишет в HIS. Итог — нормализованные DTO и диагностические ошибки с номером записи/полем, без полного медицинского файла в логе.

**Зависимости:** T1 и настоящий XML. До получения XML можно сделать только DTO, parsing infrastructure, validation и явно синтетические tests.

**Готово, когда:** реальный обезличенный пример преподавателя разбирается без потери полей; проверены namespaces, кириллица, даты, пустые значения, повтор ID, DG1, malformed/oversized XML и DTD/entity input. Собственный формат не считается заменой преподавательского.

### T4. HL7 v2.8 encoder, UAC и ACK decoder — 5 SP

**Что реализовать**

- Нормализованный пациент → `ADT^A28^ADT_A05`, `MSH/UAC/EVN/PID/PV1/DG1` по C4. Один пациент — одно сообщение; все его диагнозы в этом сообщении. Не отправлять один запрос на диагноз. Обязательные EVN/PV1 сохраняются даже без визита; `PV1||N` для пациента без визита. Имя диагноза — в DG1-3 вместе с кодом, тип — в обязательном DG1-6.
- Использовать UTF-8, `\r` для сегментов, `MSH-18=UNICODE UTF-8`, версии/поля из C4; HL7 escaping для разделителей и обратного слеша, не JSON escaping.
- Внешний ID поместить в PID-3 с authority, ФИО в XPN, дату в PID-7, пол в PID-8. Не использовать UUID message ID вместо внешнего ID.
- Каждый запрос имеет новый control ID. UAC несёт действующий access JWT: `JWT^JSON Web Token^99MEDSOFT` в UAC-1 и `MedSoftDesktop^application^jwt^Base64^<Base64(UTF8(access))>` в UAC-2; без `Bearer `, без переноса Base64-строки; API key и refresh в HL7 не попадают.
- Decoder проверяет ACK-тип, MSA-1/2/3 и correlation. Для ответа на A28: AA без корректного UUID — протокольная ошибка/неподтверждённый успех, не зелёная строка. Для probe N02 вместо UUID требуется `CONNECTED`. AE/AR не должны попадать в список успешных.
- Реализовать codec MLLP probe `NMD^N02^NMD_N02` с NCK и UAC → `ACK^N02^ACK`/MSA-3 `CONNECTED`: health-запрос не маскируется под импорт фиктивного пациента.
- Разделить encoding и framing: HL7 codec возвращает payload, MLLP adapter добавляет byte-markers.

**Зависимости:** закрытый C4/fixtures из L1/T1; T3 не нужен — входы можно создать программно.

**Готово, когда:** fixtures совпадают с HIS, тестируются кириллица/все разделители/несколько DG1, base64/UAC и маскирование, response не того message ID, malformed ACK и все AA/AE/AR.

### T5. MLLP-клиент с mTLS и отдельной проверкой — 8 SP

**Что реализовать**

- `crypto/tls`/`net` с CA verification и реальным hostname/SAN; загрузить client certificate/private key. Никаких `InsecureSkipVerify` и «принимать любой сертификат» для удобства.
- Кадр `0x0B + payload + 0x1C 0x0D`; чтение ответа до полного окончания, а не до первого `Read`. Учитывать TCP fragmentation, EOF, frame limits, deadlines и context cancellation.
- Первая версия — одно сообщение на одно mTLS-соединение, без pooling. Получить metadata server certificate именно этого MLLP-соединения и отобразить в настройках отдельно от HTTPS.
- **«Проверить MLLP»** выполняет TLS + agreed probe с JWT + разбор ответа. Оно не создаёт пациента и не объявляет канал готовым только по TCP connect.
- Классифицировать сбой: до отправки / частичная или полная отправка без достоверного ACK / валидный ACK. После начала передачи при потере ответа результат **«Исход неизвестен»**, а не «точно не импортирован».
- Никаких автоматических ADT retries, в том числе после 401/AR: обновить/проверить auth можно до новой отправки, но уже отправленный пациент требует явного решения пользователя. Неверный ACK ID не подтверждает успех.
- Тесты against fake TLS server: чужой CA, неверный SAN, expired cert, mismatch cert/key, server требует client cert, обрыв после commit, split bytes, незавершённый/слишком большой frame, cancel.

**Зависимости:** T2/T4 + fake из T1; живой MLLP HIS не требуется до общей приёмки.

**Готово, когда:** standalone TLS/framing tests воспроизводимы, ошибки различимы, исход неизвестен не запускает повтор, UI остаётся отзывчивым.

### T6. Экран импорта и пакетная обработка — 3 SP

**Что реализовать**

- File picker, путь/сводка XML, preview: внешний ID, ФИО, число диагнозов, локальные ошибки. Кнопки **«Проверить файл»**, **«Импортировать»**, **«Остановить»**.
- Явные состояния: не отправлен / локальная ошибка / отправляется / успешно + UUID HIS / дубликат / ошибка HIS / исход неизвестен. Показывать результат на каждого пациента и общий счётчик.
- Для первой версии достаточно последовательного импорта; не усложнять параллелизмом. Ошибка одного пациента не отменяет уже импортированных; при системной auth/TLS ошибке пакет останавливается, оставшиеся — «не отправлены».
- I/O в worker goroutine, UI updates через поддерживаемый Fyne main-thread API. Disable двойной запуск и редактирование connection profile во время передачи; cancel оставляет честный статус уже отправленной строки.
- Возможный явный экспорт отчёта: внешний ID, result, HIS ID, безопасная ошибка и время с секундами. Не добавлять токены/полный XML/private key; предупредить, что отчёт содержит персональные данные.
- Диагностика показывает обезличенные request type/control ID/ACK/timing/cert fingerprint; не сохраняет raw UAC. Не предлагать «показать токен» в постоянном журнале.

**Зависимости:** T1 + application interfaces; UI можно делать на fake, не ожидая T3/T5.

**Готово, когда:** demonstrable mixed batch имеет все состояния, окно не зависает, повторный click не удваивает передачу, отмена не превращает неизвестный исход в неотправленную запись.

### T7. Клиентский сертификат и удобный локальный запуск — 3 SP

**Что реализовать**

- Отдельная offline-команда/скрипт подготовки client cert: сгенерировать private key и CSR с Subject CN = введённое имя сервисного аккаунта; подписать настроенным development CA отдельным шагом. Подписание не требует работающего HIS и не выдаёт API key.
- Сертификат Client Authentication EKU, срок действия, корректная chain и ограничения leaf. Проверить несовпадение public/private key, отображение Subject/Issuer/serial/SHA-256 fingerprint.
- CA private key используется только offline при выпуске. Не сохранять его в desktop config/runtime image и не копировать в repo. Existing CA/server certificates/JWT keys/admin не сбрасываются.
- Права private key 0600 там, где ОС поддерживает; пути с пробелами корректно обрабатываются. Перезапуск helper не затирает существующий ключ без явного действия.
- `make run`, `make build`, `make test`, `make client-cert` в своём проекте. `make run` открывает desktop на host, а не пытается запустить GUI в обычном headless Docker-контейнере. Описать Fyne native toolchain dependencies и собрать macOS artifact.

**Зависимости:** формат CA/сертификатов сверяется с L5/L7. Для разработки хватает временного тестового CA, живой HIS не нужен.

**Готово, когда:** сертификат принимается fake server и затем HIS; CN виден, cert с другим CN при валидном JWT не отклоняется только из-за имени; секреты вне git; запуск нового разработчика описан воспроизводимо.

### T8. Тесты, упаковка и сквозной показ — 3 SP

**Что реализовать**

- `go test -race ./...`, `go vet ./...`; headless GUI/use-case tests отделить от ручного запуска окна. Нельзя считать mocked TLS доказательством настоящего mTLS.
- Прогнать реальный локальный fake HTTPS/mTLS сервер, XML→ADT→ACK→row result, token rotation, masking, timeout и отмену. Сертификаты генерируются в тестовом temporary directory.
- Вместе с Левом пройти [общую матрицу](lab4-lev-tasks-v1.md#6-общая-матрица-приёмки-и-показа) на реальном HIS и XML преподавателя. Сравнить UUID в desktop, карточке пациента HIS и аудите сертификата.
- README нового проекта: prerequisites, сборка/run, где взять API key/CA/client cert, два адреса соединения, объяснение ошибок/неизвестного исхода/дубликатов. Дать Льву точные команды и paths для общего system guide.
- Выпуск macOS-пакета/бинарника проверить запуском на машине показа; показать экспорт/импорт не через curl, а через настоящее desktop-окно.

**Зависимости:** автономную часть делать без HIS; финальная интеграция требует L2–L7 и реальный XML.

**Готово, когда:** функциональность подтверждена тестами и ручным desktop-показом, получен полный набор ACK/аудит/пациенты; оставшиеся ограничения перечислены честно.

| Доведение | T6 UI на fake, T8 автономные тесты/build | L6 audit, L7 stand |
| Только финал вместе | T8: настоящий desktop→HIS | L8: сверка HIS/БД/аудита |

Если HIS ещё не готов, это не блокирует разработку desktop. Если XML ещё не выдан — продолжай T1/T2/T4/T5/T7, но T3 mapping и финальную приёмку оставляй открытыми. Любые изменения wire обсуждаются в C4, а не в обход контракта только в своём коде.

## 6. Что не входит в обязательный минимум

- Переписывание Go LIS или её FHIR-клиента.
- HTTP REST endpoint для импорта медицинских данных вместо MLLP.
- Полная реализация всех HL7 v2 сообщений/таблиц/событий.
- Постоянная локальная медицинская БД, авторизация операторов desktop, Kafka, очередь фоновых retries.
- Автообновление пациента HIS при duplicate: условие прямо требует отказ без обновления.
- Авторизация по Subject CN или выдача доступа только по одному client certificate без UAC JWT.

## 7. Полезные источники

- [C4-v1 и требования к HL7/mTLS/ACK](lab4-lev-tasks-v1.md#3-общий-технический-контракт-c4-v1) — основной согласуемый профиль.
- [Fyne: Getting Started](https://docs.fyne.io/started/) — native GUI, threading, tests и desktop packaging. Учитывать требования native toolchain, не предполагать headless Docker сборкой всей GUI-части.
- [Go encoding/xml](https://pkg.go.dev/encoding/xml), [Go crypto/tls](https://pkg.go.dev/crypto/tls), [OWASP XML External Entity Prevention](https://cheatsheetseries.owasp.org/cheatsheets/XML_External_Entity_Prevention_Cheat_Sheet.html).
- Условие лабораторной требует MSA-3 для UUID/ошибки, хотя это legacy-поле; это исключение указано в C4. Не переделывать формат самовольно в обычный ERR-only ответ.
